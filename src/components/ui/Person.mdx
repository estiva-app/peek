# Person

Somebody named and pictured, resolved from a key. The package's `Person` does
the drawing; Peek's job is the lookup, the same split as `Avatar`'s
(2026-09-01).

<Canvas of={PersonStories.NamedAndNot} />

The stories here are **only the two answers the lookup can give**, because the
drawing is the package's. For the component in use, see
*Overlays/FileDetailsDialog*, *Overlays/TopicDetailsDialog*, *Topics/Files
panel* and *Messages/Reference widget* — all four places it is used.

## When

- Whenever you hold a **pubkey** and the `people` map that came back with a
  resolved object — an assignee, a lead, a file's owner.

## When not

- When you already have a name. Then you want `Avatar` and your own text, not a
  key lookup that will miss.
- To put a key on screen. It cannot: the package's component takes a name and a
  picture and will not accept anything else. That is deliberate — FEE-1 was a
  truncated pubkey shown where a person's name belonged.

## How

```tsx
import { Person } from '@/components/ui/Person'

<Person pubkey={object.slots.lead.value} people={object.people} size={16} />
```

- `people` is absent in the states where nothing resolved, and that is a normal
  case rather than a missing prop.

## What it owns

- **The two-step lookup:** the picture the relay published for that key, else
  Peek's own portrait for that name.
- **What an unresolved person looks like.** When nobody has published a name,
  the package draws an em dash — not the key, not "Unknown", not a blank. Until
  UIG-17 no story in Peek showed that at all, because every fixture in the app
  has tidy named people in it; **Unnamed** above is that state.
