# PersonRow

One row in a side list — a topic, a person, a group, a huddle or a folder — with
its icon or photo, its name, its unread mark and a hover menu.

<Canvas of={PersonRowStories.Dm} />

## When

- In any sidebar list: topics, people, starred, open work, the file tree.
- Pass only the handlers that apply. The hover menu appears **only** when at
  least one of its items would be there, so a row with nothing to offer has an
  inert ⋯ rather than an empty menu.

## When not

- For a row in the main pane. This is a side-list row: 16px glyph, one line,
  a hover affordance at the right. A conversation is `ConversationCard`.
- Building the menu yourself. It is `TopicMoreMenu` — the same one the
  conversation header opens, which is the whole point: one menu, two places to
  open it (PEE-2).

## How

```tsx
import { PersonRow } from '@/components/ui/PersonRow'

<PersonRow
  name={topic.title}
  type="topic"
  topicStatus={topic.isResolved ? 'resolved' : 'unresolved'}
  isUnread={topic.unread}
  isSelected={topic.id === current}
  onClick={open}
  onOpenDetails={openDetails}
  followAction={topic.following ? 'unfollow' : 'follow'}
  onToggleFollow={toggleFollow}
/>
```

- `onRemove` **replaces** the hover ⋯ with an ✕ — that is how Open work rows let
  somebody take an item off the list.

## What it owns

- **Whether there is a menu at all**, worked out from which handlers arrived.
- **Showing that a row is followed while it is idle** (FOL-30). Without it a
  followed-but-read row and an unfollowed one look identical, and only the first
  will ever light up.
- **Labels that say which direction will work** — add or remove, follow or
  unfollow — passed straight through to the menu.
- **The glyph**, through `TopicState`, so a row in a list and the header of the
  thing it opens agree about what it is.
