# AttachmentChips

The files under a message you are writing or editing, in the order they were
attached.

<Canvas of={AttachmentChipsStories.MessageFiles} />

<Canvas of={AttachmentChipsStories.Mixed} />

## When

- Under the text in any box that can hold a file: the composer, and the two
  message-edit boxes.
- Always with the whole chip list. Each chip carries its own remove handler, so
  the caller passes the list and nothing else.

## When not

- For a file that is already sent. These are *pending* — every card is drawn
  with `pending`, which is what gives it its progress and its remove control.
- With an empty list as a way of drawing an empty state. It renders nothing at
  zero, deliberately.

## How

```tsx
import { AttachmentChips } from '@/components/ui/AttachFiles'

<AttachmentChips chips={uploads.chips} />
```

- Each chip is an `EditAttachmentChip`: a key, a name, a size, a content type,
  a preview URL and its own `onRemove`.

## What it owns

- **The states a pending file can be in** — uploading, ready and failed —
  through `pendingAttachmentNote`, which turns a chip's status into the note
  the card shows. This is the **only** place in Peek those states are drawn.
- **Drawing nothing at zero**, so no call site guards it.
- **The order**, which is the order they were attached and nothing else.
