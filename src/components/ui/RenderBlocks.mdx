# RenderBlocks

Formatted text laid out as paragraphs, lists, headings, quotes and code — for a
message, or for another app's item shown inside one.

**Seen in** — every story on *Messages/MessageBody*, which is built on it. It
has no page of stories of its own because there is nothing it draws that
`MessageBody` does not.

## When

- When you have marker text and want the blocks, without the mentions, the
  chips and the reference cards `MessageBody` adds.
- For another app's rich text arriving in a foreign object.

## When not

- For a Peek message. That is `MessageBody`, which is this plus everything a
  message has.
- Expecting it to resolve anything. It renders a tree; whoever calls it supplies
  the resolved objects and the run renderer.

## How

```tsx
import { RenderBlocks } from '@/components/ui/MessageBody'

<RenderBlocks value={slot.value} format={slot.format} hideStandalone />
```

- `hideStandalone` drops reference blocks that stand on their own, for a caller
  that is going to draw those references itself. Without it they stay in the
  flow.

## What it owns

- **Turning marker text into a tree**, through the protocol's `toRenderTree`,
  so no caller parses the dialect itself.
- **Filtering standalone references when asked**, in one place rather than at
  each call site.
- **Whatever `Block` decides about unknown types** — which is to render their
  inline text rather than drop them, because §13.3 requires it and because a
  silently empty block is indistinguishable from one the reader may not see.

## Props

| | |
| --- | --- |
| `value` | the marker text |
| `format` | the format it is in |
| `renderRun` | how to draw one run of inline text |
| `resolved` | objects the text refers to |
| `hideStandalone` | drop reference blocks that stand alone |
