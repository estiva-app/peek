# PartCard

One block of another app's object — a paragraph, a table or a picture from a
Ship description — shown live inside a message.

<Canvas of={PartCardStories.Paragraph} />

`PartCard` reads the block; `PartCardView` draws what the read gave. The stories
draw the view, because the read needs a relay.

## When

- Under a message whose text holds a pasted block link, and that carries its
  `part` tag (SPEC §13.6.1). `MessageBody` places it; nothing else needs to.
- Above a comment anchored to one block of the object it is on (§13.6).

## When not

- A link to a whole object → the kit's card under the message, `MessageCard`.
- A file attached to the message itself → the package's `AttachmentCard`.

## How

```tsx
import { PartCard } from '@/components/ui/PartCard'

<PartCard address={part.address} block={part.block} />
```

<Canvas of={PartCardStories.Long} />

## What it owns

- **Five states, in the kit's words** (`PartCard`'s `state`, SPEC §13.6.1):
  shown; "This part was deleted"; "This part can't be shown", which opens the
  whole file; "A part of this issue deleted", only when a deletion the protocol
  trusts names the file (`readAbsence`); "A part of this issue not available".
  The last two show no title and no text.
- **The cut.** A block taller than 160px goes behind the package's `ShowMore`
  and opens in place. A picture is never cut.
- **The way into the app.** Its title, a link to the block in the app it
  lives in, in a new tab. Words, not a link, when the app gave no link. There
  is no "Open in" button: it said again what the title does (Katerina, 31 Oct).
- **Staying live.** It reads again every 30 seconds while the tab is visible,
  and when the tab comes back.
