# SuggestionPopover

The box a type-ahead popup hangs in — the ones that open on `@`, `!@`, `[` and
`/` (D47).

**Seen in** — *Overlays/Menus*, which stands each of the four menus up inside
it. There is no story of the box alone, because an empty box is not a picture of
anything.

## When

- Around any editor type-ahead list that follows the caret.
- Handing it the caret's rectangle. `open` follows that rectangle: a missing one
  closes the popover rather than unmounting it, which is what keeps Base UI's
  exit animations.

## When not

- As a `Menu`. That is the whole point of it. A menu takes roving focus and
  typeahead, which would take the keyboard away from the person typing. An
  anchored `Popover` never takes focus, so the caret stays in the text and the
  editor's suggestion plugin keeps the arrow keys.
- Expecting `onOpenChange`. There deliberately is none: **the plugin owns this
  popup's life.** It mounts the renderer when the query starts and destroys it
  when the query ends, so an outside press — or an Escape that Base UI wanted to
  act on — would close a panel the plugin still believed was open. Escape is
  handled one level up, where it also has to decide whether it is closing the
  menu or cancelling an edit.

## How

```tsx
import { SuggestionPopover } from '@/extensions/SuggestionPopover'

<SuggestionPopover rect={caretRect} width={280} maxHeight={360} ariaLabel="People">
  {rows}
</SuggestionPopover>
```

## What it owns

- **Where the box goes.** `side="top"` is a *preference* Base UI flips when
  there is no room, which is the fix from 8 September — a menu drawn off the top
  of the window when you edited a message near the top of the stream. That is
  the positioner's job now, not arithmetic of ours.
- **Staying on screen.** Base UI clamps to the viewport, so the hard-coded menu
  width each caller used to pass — because the old container could not measure
  its own child — is gone with it.
- **The panel and its scrolling.** The box is the package's `MenuPanel`, capped
  at the room actually available and scrolled in the package's `ScrollArea`
  (D40), rather than each menu carrying its own max height and a native bar.

## What it replaced

Each of the four popups used to build its own shell — create a div, position it
fixed, set a z-index, append it to the body — and then run a shared 69-line
helper to read the caret's rect, measure the popup, prefer above, fall below,
clamp to the edges, and do it again on the next frame because the first pass ran
before React had rendered anything to measure. Three copies of the container and
one helper, all of it a re-implementation of what the package's `Popover` does
through Base UI's positioner.
